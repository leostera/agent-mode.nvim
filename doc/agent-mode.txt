1. INTRODUCTION                                             *agent-mode-intro*

Put the cursor on a line, press your key, and type a question or an
instruction. Answers render as Markdown right under the line; changes land in
the buffer as one undo step. It works with the agent CLI you already use:
Claude Code, Codex, OpenCode or pi.

Every request from one Neovim goes to the same conversation with the agent,
so you can refer to earlier answers. The agent can also run Lua in your
Neovim to ask your language servers or show you things in a tab.

==============================================================================
2. SETUP                                                    *agent-mode-setup*

Requires Neovim 0.12 or newer and an agent CLI, installed and logged in.
Nothing else is required: the plugin loads its commands at startup and the
rest when you first use it. Map a key to |<Plug>(AgentMode)|: >lua

    vim.keymap.set({ "n", "x" }, "<leader>a", "<Plug>(AgentMode)")
<
Pick your agent with |vim.g.agent_mode| (works even before the plugin
loads) or with `setup()`: >lua

    vim.g.agent_mode = { agent = "claude" }
    -- or
    require("agent_mode").setup({ agent = "claude" })
<
Check your setup with: >vim

    :checkhealth agent_mode
<
                                                           *<Plug>(AgentMode)*
<Plug>(AgentMode)       Normal and Visual mode. Open the prompt below the
                        cursor and ask about, or change, the code at the
                        cursor or in the selection.

==============================================================================
3. USAGE                                                    *agent-mode-usage*

While a request runs, the line shows what the agent is doing. You can keep
editing and send more requests; in one conversation they run one at a time
(see `session.enabled`). Edits are applied only if the lines they replace are still
what the agent saw.

These keys exist only in buffers that show an answer:

  <CR>      on a line with an answer: step into it to scroll, select and
            yank; `q` goes back
  ]a  [a    next / previous answer
  <Esc>     dismiss the answer nearest the cursor

Change them with `answer_keymaps`.

==============================================================================
4. COMMANDS                                              *agent-mode-commands*

                                                                  *:AgentMode*
:AgentMode              Open the prompt, like |<Plug>(AgentMode)|.

:AgentMode ask {text}   Run {text} as an instruction at the cursor.

:AgentMode cancel       Stop the requests on the cursor line, or all of
                        them if there are none on it.

:AgentMode dismiss[!]   Clear the answer nearest the cursor; with ! clear
                        all of them.

:AgentMode agent [name] Show the agent, or switch to {name}.

:AgentMode config       A menu to change the agent, model, thinking, Lua,
                        session and prompt settings for this Neovim,
                        start a new session, or copy the settings as
                        Lua. Drawn by snacks.nvim when installed, else
                        |vim.ui.select|.

:AgentMode new          Start a new session with the agent, and let go of
                        an attached agent.

:AgentMode attach       Show how to attach an agent you run yourself, and
                        copy what to tell it. |agent-mode-attach|

:AgentMode log          Show the last request's prompt, command, session
                        and output.

==============================================================================
5. SETTINGS                                              *agent-mode-settings*

                                                             *vim.g.agent_mode*
Settings come from the defaults, then |vim.g.agent_mode| (a table, or a
function returning one), then `setup()` and `configure()`. Unknown keys are
reported by |:checkhealth|. Defaults:
>lua
    {
      agent = "pi",            -- "claude", "codex", "opencode", "pi",
                               -- "axo", or a function (|agent-mode-agents|)
      cmd = nil,               -- path to the agent's executable
      model = nil,             -- nil: the agent's default
      thinking = nil,          -- reasoning level, passed to the agent
      system_prompt = nil,     -- your instructions, added to agent-mode's
      args = {},               -- extra CLI arguments for the agent
      input = "cursor",        -- "cursor": prompt below the cursor;
                               -- "cmdline": |vim.ui.input|
      answer_keymaps = { enter = "<CR>", dismiss = "<Esc>",
                         next = "]a", prev = "[a" },
      max_lines = 2000,        -- longer buffers are sent as a window
      code_action_timeout_ms = 1000,
      luamode = "confirm",     -- the agent's Lua: "confirm", "allow", false
      luamode_timeout_ms = 10000, -- for Lua that waits (ctx.async)
      session = {
        enabled = true,        -- one agent session per Neovim
        mode = "start",        -- no agent attached: "start" one,
                               -- "attach" (wait for one), or "ask"
      },
      axo = { session = "self", cmd = "axo" },
    }
<
`keymap` is deprecated: map |<Plug>(AgentMode)| instead.

6. AGENTS                                                  *agent-mode-agents*

Each request runs the agent's CLI with its usual tools and the nvim-mcp
server, continuing the same session. The buffer you asked from changes only
through nvim-mcp's tools, since it may have unsaved edits; other open
files the agent changes are reloaded, unless they have unsaved changes.

  agent       runs                                      thinking
  "claude"    claude --print --permission-mode           low ... max
              acceptEdits --mcp-config ...
  "codex"     codex exec --sandbox workspace-write       minimal ... high
              -c mcp_servers.nvim-mcp...
  "opencode"  opencode run --standalone --auto           n/a
  "pi"        pi --print --tools +codemode               off ... xhigh
              --extension pi/pi-nvim.ts

A custom agent is a function from a request to a command: >lua

    agent = function(request)
      -- request: system_prompt, prompt, model, thinking, args, session,
      -- mcp = { command, args }: the nvim-mcp server for this Neovim
      return { argv = { "my-agent" }, stdin = request.prompt, env = {} }
    end
<
The agent works through the MCP tools (see |agent-mode-attach|); when it
uses none, what it prints on stdout is shown as the answer.

"axo" hands requests to an Axo Session's agent, which edits files itself;
agent-mode reloads the buffer afterwards.

==============================================================================
7. LUA IN NEOVIM                                              *agent-mode-lua*

For what only Neovim has (language servers, unsaved buffers, windows,
plugins), the agent can send Lua to the run_lua tool; what it returns goes
back to the agent as the tool's result. By default you see the code first:
`y` runs it, `a` runs it and the rest of the request's Lua, `n` skips it.
The code runs with your editor's permissions.

The code gets `ctx` (bufnr, win, row, col, file, filetype, selection,
instruction, async), `describe(topic)` to discover what this Neovim has, and
helpers in `am`: `am.scratch()`, `am.lsp()`, `am.position_params()`,
`am.lines()`.

==============================================================================
8. LUA API                                                    *agent-mode-api*

require("agent_mode").setup({opts})                       *agent_mode.setup()*
    Set the settings: {opts} over |vim.g.agent_mode| over the defaults.
    Optional.

require("agent_mode").configure({opts})               *agent_mode.configure()*
    Change some settings, keeping the rest.

require("agent_mode").run({instruction}, {opts})            *agent_mode.run()*
    Run {instruction}. {opts}: `bufnr`, `position` ({row}, {col}),
    `selection` ({start_row}, {end_row}), `on_done` (called with an error
    or nil).

require("agent_mode").prompt()                           *agent_mode.prompt()*
    Open the prompt, as |<Plug>(AgentMode)| does.

require("agent_mode").new_session()                 *agent_mode.new_session()*
    Start a new session, and let go of an attached agent.

require("agent_mode").attach()                           *agent_mode.attach()*
    Show how to attach an agent, as `:AgentMode attach` does.

require("agent_mode").attached()                       *agent_mode.attached()*
    Whether an agent is attached: listening, working, or seen in the last
    15 seconds.

10. ATTACHED AGENTS                                        *agent-mode-attach*

An agent you run yourself (in another terminal, tmux, anywhere) can take
your requests too. the nvim-mcp server, `bin/nvim-mcp`, gives it
these tools, each on a request's `context_id`:

  wait_for_request   wait for the next request made at the cursor
  get_context        the buffer, cursor and language server state now
  edit               line edits to the buffer, refused if the lines changed
  lsp_rename         rename the symbol at the cursor
  code_action        run one of the listed code actions
  show_answer        Markdown under the user's line
  run_lua            Lua in Neovim, under `luamode`
  set_status         a few words next to the line
  finish             end the request

Add the server to your agent once (`:AgentMode attach` shows the commands
with paths filled in), start it in any folder, and tell it to call
wait_for_request in a loop. While it listens, requests go to it.
The server finds Neovim by `--server`, `$NVIM_MCP_SERVER`, `$NVIM`, then
the Neovim in the agent's project (the closest working directory at or above its folder), then the
one you used last, focused or asked from (each Neovim registers itself under
`stdpath("state")/nvim-mcp/servers`).

With no agent attached, `session.mode` decides: "start" starts your agent,
"attach" waits for one and shows how to attach it, "ask" asks each time.
